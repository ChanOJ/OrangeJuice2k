# OrangeJuice99: context for Claude sessions

Static archive of the ASP version of Orange Juice online from about September 1999 to
November 2000 (renamed from OrangeJuice2k: the edition started in 1999). Follow
`~/Code/OrangeJuice98` (README: statify, verify_build, exclude globs, hardening, deploy) rather
than redesigning. GitHub repo `ChanOJ/OrangeJuice99` (public). `site/` (~300 MB) is
generated on the Mac and **committed**. Process: rebuild locally (`scripts/publish.sh`: build +
checks, no deploy), commit `site/` in the same PR as the script change, merge = CI deploys
(`.github/workflows/deploy.yml`). Never deploy by hand, never `git add -A`; a leak in git history
is permanent, so `verify_build.py` and `check_excludes.py` must pass before any commit of `site/`.

## Hard rules

- `private/` is git-ignored and must stay so: it holds the original sources with plaintext SQL and
  admin passwords (`global.asa`, `admin/global.bak`, `admin/index.asp`), the database (member
  e-mails, plaintext passwords, IPs, logins) and private photos. Never copy its content into the
  repo, a commit, a PR or a published page, except rendered public data.
- The project must not depend on the NAS (`/Volumes/archive`): everything needed is in `private/`.
- Never run the ASP. Everything published is static HTML.

## Findings (details in `private/notes/`)

- **Engine**: every page includes `_inc/parameters.inc` and `_inc/functions.inc`. `OpenHTML_`
  loads `skins/<skin>/<page>.html` (fallback `skins/tonic/`), expands `$$TOP$$`, `$$BOTTOM$$`...,
  then pages fill `$$TOKEN$$` and `$$BEGIN$$..$$END$$` loops. Static pages (faq, links, credits)
  go through `404.asp`. A generator can reuse the templates as they are (`schema_report.md`).
- **Skins**: `tonic` is the full set; others override a few files. Choice was cookie `OJ_SKIN`,
  then per-IP list, then `Day MOD 4` rotation, xmas and snow variants of tonic. The archive
  renders all 13 real skins (see `docs/data-model.md` §9); default is always tonic, the
  2000 skin of the day was dropped on purpose (an archive should look the same on every visit).
- **Database**: `private/db/OJUICE_Data.MDF`, SQL Server 2000 (dbi_version 539), read with
  `scripts/mdf/mdf.py` (`python3 -I scripts/mdf/schema.py FILE.MDF out.txt`). 43 tables; NEWS
  5615 rows (1998-05 to 2006-09), PEOPLE 25125, GROUPS 1212, PARTIES 751, PICTURES 1640, ONELINER
  55695, CHARTS 4233. Procedure text (syscomments, object id 6) is readable, e.g. `oj_listnews`.
  Full extraction (README "Extracting the database") → `private/db/ojuice.sqlite`: 42 tables,
  1.5 M rows, 0 decode errors, row counts equal to the IAM counts, LOBs and cp1252 accents OK,
  checked against Wayback (article 1111, 77 news of 2000 index pages). Work from the SQLite file;
  `_procedures` holds the stored procedure text (reproduce e.g. `oj_listnews`: 20 per page,
  `ORDER BY dt DESC`).
- **Era mismatch**: the DB is the 2006 state shared with the next site generation (id3/id3x).
  PEOPLE was recreated in 2005 with other columns (idgroup1/2 -> LINKS, pic_ext, ...); the people
  pages redirect to `/v3.htm` only since the v3 launch, so the archive renders them (2460 sheets;
  by owner decision real name, e-mail as `local@????`, birth date as `dd/mm/????`, sex, ICQ number
  and ID photo are shown; password, logins, IPs, French department hidden; see `docs/data-model.md`). News ids are continuous across the switch
  (2000-12 ends at id 1787, 2001-01 starts at 1789). **Cut-off decided: news with
  `dt < '2000-11-20'`** (Orange Juice v3 launched on 2000-11-20, per the 2000-11-21 mailing in
  `Sites web/work/ojuice2/spamOJ/spam.txt` on the NAS): 1174 news, 1998-05-11 to 2000-11-18, last id 1615. Apply the same
  date to other dated content (oneliner, parties, pictures, charts) when it is shown as "current". News per year: 1998 64, 1999 129, 2000 1139, 2001 1339, then fewer until 2006.
- **Write paths to drop** (replace with an "archived, read-only" notice): oneliner post, add
  news/article/party/picture/group forms, chart votes, profile edit and sendpass, admin,
  click counters (`gonlink.asp`, `redirban.asp`, `width.asp`; link straight to the target),
  skin cookie writes, `ielog.asp`.
- **Gone for good**: `ix_*` FTP search (dead servers), Nectarine stream status, cnxweb counter,
  ICQ status images. Banner images (`pictures/pubs/`) were not found anywhere.
- **Never publish**: `global.asa`, `admin/`, `_data/`, `*.bak`, `*.aspsav`, `.DS_Store` (ignored
  by all scripts, never uploaded), `pictures/photo_private/`, `handles/pictures/bak/` and the ID
  photos of people not in the archive, debug pages (`env.asp`, `test.asp`, `tm.asp`,
  `av.asp`, `a.asp`, `c.asp`, `gz1/gz2.asp`, `width.asp`, `1.htm`, `test.htm`,
  `admin/_list_application.asp`), `archives/vncviewer/`, zips holding executables, any `.asp`/`.inc`
  source. Redact e-mails like OrangeJuice98 (`nick@????`).
- **Search**: client-side, JSON indexes built by `statify.py` + `scripts/oj.js` (no Pagefind).
- **Old URLs**: query-string URLs (`view_article.asp?id=`, `index.asp?p=`) need a Bunny Edge
  Script that redirects to the static pages.
- **Wayback**: only ~53 pages of this era (17 `index.asp?p=N` of 2000-11, 2 articles): useful to
  check the rendering, raw CDX in `private/notes/wayback/`.
- **Secrets considered compromised**: the SA passwords of DSNs OJUICE and CNXWEB and the admin
  password; the user should rotate them if reused anywhere.
